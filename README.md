# Browser MCP Server (C#)

MCP-сервер на базе .NET для интеграции локальных языковых моделей с браузером Google Chrome. Позволяет ИИ-ассистентам автономно выполнять навигацию, парсинг контента и взаимодействие с веб-интерфейсами через Chrome DevTools Protocol (CDP).

## Установка и запуск

> **Примечание:** Готовые автономные сборки для Windows, Linux и macOS доступны в разделе [Releases](../../releases). Исходный код предназначен для самостоятельной сборки или доработки.

### Запуск готовой сборки
1. Скачайте архив для вашей операционной системы из раздела Releases и распакуйте его.
2. Откройте терминал в папке с распакованными файлами.
3. Запустите сервер (терминал должен оставаться активным для работы MCP-протокола):
   - **Windows:** `.\BrowserMCPServer.exe`
   - **Linux / macOS:** `./BrowserMCPServer`

> **Примечание для macOS:** При первом запуске может потребоваться снять атрибут карантина:  
> `xattr -d com.apple.quarantine BrowserMCPServer`  
> **Примечание для Linux/macOS:** Убедитесь, что файл имеет права на выполнение:  
> `chmod +x BrowserMCPServer`

### Параметры командной строки

| Параметр | Описание | Пример |
|----------|----------|--------|
| `--headless`, `-h` | Запуск в фоновом режиме (без отображения окна браузера) | `BrowserMCPServer -h` |
| `--proxy=<address>` | Настройка прокси-сервера | `BrowserMCPServer --proxy=127.0.0.1:8080` |
| `--proxy=<user>:<pass>@<host>:<port>` | Прокси с авторизацией | `BrowserMCPServer --proxy=user:pass@proxy.example.com:8080` |

## Настройка Chrome

Для работы сервера браузер должен быть запущен с активным портом удалённой отладки (CDP). Это позволяет MCP-серверу подключаться к браузеру и управлять вкладками.

### Обязательные аргументы запуска
- `--remote-debugging-port=9222` — открывает локальный порт для подключения MCP-сервера.
- `--user-data-dir="<путь_к_папке>"` — **обязательный параметр**. Создаёт изолированный профиль, чтобы действия бота не конфликтовали с вашей основной сессией, куки и историей.

### Примеры запуска для разных ОС

**Windows (через cmd или ярлык):**
```cmd
"C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9222 --user-data-dir="C:\chrome-mcp-profile"
```

**macOS (через терминал):**
```bash
/Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome --remote-debugging-port=9222 --user-data-dir="$HOME/chrome-mcp-profile"
```

**Linux (через терминал):**
```bash
google-chrome --remote-debugging-port=9222 --user-data-dir="$HOME/chrome-mcp-profile"
# или для Chromium:
chromium-browser --remote-debugging-port=9222 --user-data-dir="$HOME/chrome-mcp-profile"
```

> **Рекомендация:** Создайте отдельный ярлык, `.bat`/`.sh` скрипт или alias для запуска браузера с этими параметрами. После запуска Chrome MCP-сервер автоматически подключится к порту `9222` при инициализации клиента.

## Конфигурация клиента

Добавьте конфигурацию сервера в настройки вашего MCP-клиента. Пути к исполняемым файлам различаются в зависимости от ОС.


### Windows
```json
{
  "mcpServers": {
    "browser-custom-csharp": {
      "command": "C:/path/to/BrowserMCPServer.exe",
      "args": [],
      "env": {}
    }
  }
}
```

### Linux и macOS
```json
{
  "mcpServers": {
    "browser-custom-csharp": {
      "command": "/home/user/bin/BrowserMCPServer",
      "args": [],
      "env": {}
    }
  }
}
```

**Важные замечания:**
1.  Используйте **абсолютные пути** к исполняемому файлу.
2.  В путях на Windows допустимы как прямые (`/`), так и обратные (`\\`) слеши.
3.  Убедитесь, что файл имеет права на выполнение (Linux/macOS):
```bash
chmod +x /path/to/BrowserMCPServer
```

## API и инструменты

Сервер предоставляет следующие инструменты (Tools) для вызова моделью:

### Навигация
| Инструмент | Описание |
|------------|----------|
| `Navigate(url)` | Открыть URL в активной вкладке. Базовое действие перед началом работы. |
| `GetUrl()` | Получить текущий адрес страницы. |
| `Reload()` | Перезагрузить текущую страницу. |

### Чтение контента
| Инструмент | Описание |
|------------|----------|
| `GetContent()` | Извлечь видимый текст (заголовки, параграфы). Оптимизирован для понимания контекста моделью. |
| `GetLinks()` | Получить список ссылок в формате `[Текст] -> [URL]`. |
| `GetHtml()` | Вернуть полный HTML-код страницы (использовать с осторожностью из-за размера токенов). |
| `Screenshot(name, selector?)` | Сделать скриншот. Возвращает путь к файлу. |

### Взаимодействие
| Инструмент | Описание |
|------------|----------|
| `Click(target, mode, extra, timeout)` | Клик по элементу. `mode`: "css" (селектор), "text" (текст кнопки), "attr" (атрибут). |
| `Fill(selector, text)` | Ввод текста в поле `input` или `textarea`. |
| `Select(selector, value)` | Выбор значения в `<select>`. |
| `Hover(selector)` | Наведение курсора (для выпадающих меню). |
| `Evaluate(js)` | Выполнение произвольного JavaScript кода в контексте страницы. |

### Управление вкладками
| Инструмент | Описание |
|------------|----------|
| `GetTabs()` | Список вкладок: `[ID] Title | URL [ACTIVE]`. |
| `SwitchTab(id)` | Переключение на вкладку по идентификатору. |
| `NewTab(url?)` | Открытие новой вкладки. |
| `CloseTab(id?)` | Закрытие вкладки (по ID или текущей). |

## Инструкции для модели (System Prompt)

Рекомендуемый системный промпт для настройки поведения локальной LLM.

```text
Ты — автономный браузер-ассистент с доступом к инструментам управления Chrome. Твоя задача — самостоятельно находить информацию и выполнять задачи пользователя.

## Доступные инструменты
- Навигация: Navigate, GetUrl, Reload
- Контент: GetContent (основной текст), GetLinks (список ссылок), GetHtml, Screenshot
- Действия: Click (поддерживает mode: css/text/attr), Fill, Select, Hover, Evaluate (JS)
- Вкладки: GetTabs, SwitchTab, NewTab, CloseTab

## Алгоритмы работы

1. Поиск информации:
   - Используй Navigate для перехода по прямой ссылке или через поисковик.
   - Анализируй результат через GetContent.
   - Для перехода используй GetLinks для поиска релевантной ссылки, затем Click.

2. Работа с формами:
   - Найди поля через анализ контента.
   - Используй Fill для ввода данных.
   - Используй Click с mode="text" для кнопок с понятным текстом.

3. Многозадачность:
   - Используй вкладки для параллельного сбора данных.
   - Всегда вызывай GetTabs перед переключением, чтобы знать актуальные ID.

4. Обход препятствий:
   - Если встречаешь капчу или проверку безопасности — сообщи пользователю и остановись.

## Правила поведения
1. Действуй автономно, не запрашивай подтверждение каждого шага.
2. Все действия применяются к активной вкладке.
3. Не угадывай сложные CSS-селекторы — используй поиск по тексту (mode="text") или атрибутам.
4. Если инструмент вернул ошибку, попробуй альтернативный метод (другой селектор, перезагрузка).
5. На простые вопросы (факты, код, перевод) отвечай сразу, не запуская браузер.

## Обработка ошибок
- Таймаут: Проверь загрузку страницы или увеличь ожидание.
- Элемент не найден: Попробуй другой режим поиска (text вместо css).
- Вкладка не найдена: Обновите список через GetTabs.
```
